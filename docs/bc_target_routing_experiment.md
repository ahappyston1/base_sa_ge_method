# BC 监督目标切换实验

分支 `codex/bc-target-routing`；配置 `configs/experiment_bc_targets.yaml`。从原BC出发，全程300轮，不从旧r225权重续训。不包含之前的A repair、tail实验或自编码器。

## 本次实现

保留骨干、数据与种子、LR=0.15、FedAvg、原BC的A/B/C路由、教师EMA和特征权重0.10。路由标签仍用于诊断，但各组内部可以采用不同监督目标。

1. 第31轮起，为客户端每个无标签样本收集教师双弱增强预测。一次客户端参与期间，历史只读；收集到的重复访问概率先平均，结束时才更新一次历史。历史EMA旧值0.7、新值0.3，至少两次过去参与，且距上次观察不超过20轮才算成熟；过期后重新累计。历史持久化在每客户端checkpoint，不上传到服务器聚合。
2. 第61–120轮，目标切换强度由0余弦增至1。开始轮次不是成熟性的替代条件：A切换还需要成熟历史。
3. 几何充分支持原类别的A保留原硬目标。教师两个视图与历史都支持原类别（视图置信度均>=0.85，历史>=0.75）的A也保留。这里几何支持采用已有真标签参考的半径、相对margin及正可信度。
4. 其余具有成熟历史的A进入不确定处理。若教师两个视图、历史一致支持替代类别，且替代类别得到有效几何参考支持，则转向教师与历史的软目标。否则先尝试候选集合。
5. 候选集合取融合分布最高两类与原学生类别的并集，最多三类；保留原类别以限制突然误改。融合分布在集合中的质量至少0.8，并且历史成熟或当前可靠性评分>=0.6时，使用 `-log(sum(p[c], c in candidates))`。不足时退到特征学习。候选集合不保证包含真类，日志专门统计遗漏。
6. B也采用候选/软目标/特征三种任务：稳定时用软目标，否则按上述规则判断候选集合。可靠性系数由原双视图评分线性映射（0.4至0.9对应0至1），历史成熟时再乘分布一致性。B总分类权重不守恒，不按剩余样本数重新归一化。原BC过渡阶段的学生B项仍按原BC系数保留，新B目标在教师分支内渐进替换。
7. A目标按切换强度从原硬CE过渡到新目标，不额外增加一份相互冲突的分类loss。脱离硬答案的A同步渐减旧标签原型写入，到强度1时停止；不将替代教师类别直接写成硬原型标签。它们同时渐增获得BC特征任务；原B/C特征学习保留。

## 明确的边界

- 没有把训练隐藏真标签用于历史、选样、目标或阈值。隐藏真值只供事后诊断。
- 没有独立的逐类别教师概率校准器。类别差异目前通过真标签几何参考的有效性、半径和margin进入决策，不声称获得无偏正确概率。没有硬编码猫/狗/青蛙减权。
- 跨轮稳定可能是持续犯错；几何参考与模型也不是独立裁判。候选集合可减轻过早强制分类，但本身不会解决集合内部的类别混淆。
- 当前阈值和60–120渐增日程是固定首版假设，不使用测试acc动态选择。
- A被释放后新增特征任务会增加总特征监督范围，故这是统一目标切换实验，不能将结果单独归因于某一组件。
- 保留原每epoch参考刷新频率及原BC教师每轮初始化方式。本地特征、历史可能随全局模型变化而过时，20轮时效只能缓解，不能完全消除。
- 旧BC checkpoint缺少样本历史，拒绝以本实验身份续训；本实验自己的完整checkpoint支持恢复。

## 诊断口径

`dynamics.csv` 增加 `target_gate` 及每个预测类别 `target_c{类别号}_...`：

- `history_mature`：A/B中具有成熟历史的访问量。
- `a_changed/a_changed_correct`：A目标切换的覆盖和其中原答案正确数。后者不是必然误伤，应结合新目标判断。
- `candidate_visits/candidate_contains_truth`：候选访问量和集合包含真类的数量。
- `soft_visits/soft_correct`：软目标访问量和目标argmax正确数。
- `soft_a_fix/soft_a_harm`：原A答案错而新目标argmax对、以及反方向。它们不表示实际模型已完成纠正。
- `feature_only_visits`：不承担新分类目标的访问量；渐增未完成时仍有原分类目标残留。
- `a_hard_released_correct_mass/a_hard_released_wrong_mass`：移出原硬标签分支的权重，不代表这些样本完全不再学习；也不等于原型写入实际质量。
- `b_old_mass/b_new_mass`：目标切换分支的名义权重变化，不含外层lambda、BC教师渐增和aux系数，也不衡量完整软目标错误质量。

这些量按重复训练访问累计，不是独立图片数。原geometry_audit、A/B伪标签正确率、原有wrong_mass指标仍以原路由和硬标签定义，不能把它们当作新候选/软目标的真实错误监督。总分类loss仍可由各项effective loss还原。

## 上服务器

本地推送：

```bash
git push -u origin codex/bc-target-routing
```

服务器原仓库中创建独立工作目录（不切换正在跑的目录）：

```bash
git fetch origin
git worktree add -b codex/bc-target-routing ../SAGE-bc-target-routing origin/codex/bc-target-routing
cd ../SAGE-bc-target-routing
```

激活原Python环境，准备数据路径。GPU 0空闲后启动：

```bash
nohup bash scripts/train.sh --config configs/experiment_bc_targets.yaml --gpu_id 0 --run_id "bc_targets_$(date +%Y%m%d_%H%M%S)" > bc_targets_launch.log 2>&1 &
```

额外保存30/60/90/120/225轮完整checkpoint。不会自动避让已有GPU任务。比较原BC时同时看覆盖、候选遗漏、软目标误改、逐类有效监督和中后段acc，不能单靠loss下降判断有效。
