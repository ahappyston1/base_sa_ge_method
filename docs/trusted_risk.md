# trusted_lr015_risk：early 基础上的 A 组风险权重实验

## 运行

在服务器项目根目录、已安装原项目依赖的环境执行。GPU 0 按实际空闲卡调整：

```bash
bash scripts/run_experiment.sh trusted_lr015_risk 0 7 --dry-run
bash scripts/run_experiment.sh trusted_lr015_risk 0 7
```

需要后台运行时：

```bash
nohup bash scripts/run_experiment.sh trusted_lr015_risk 0 7 > trusted_lr015_risk_launch.log 2>&1 &
```

每次运行生成带时间戳的新目录，不覆盖原版和 early。请从头训练，不从旧 early 的中间检查点继续；开启风险模块后，检查点几何配置校验会拒绝旧配置。

直接对照是 trusted_lr015_early，原 trusted_lr015 仍作为基准。保持 CIFAR10、alpha=0.1、20 客户端/8 在线、每类 500 标签、划分种子 0、模型/抽样种子 7、原骨干、LR 0.15、300 轮余弦日程、本地 5 epoch、16 workers。沿用 early 的第 31—60 轮渐进启动。不要为了冒烟测试把完整实验的 max_rounds 改成几轮后再续训，这会改变训练日程。

## 实际改动和耦合边界

仅替换 A 的可靠性权重，不乘在旧权重上。A 仍学原分类器硬标签，路由不增加几何门槛。B 仍使用原弱增强软目标和原置信度×trusted 权重，C 没有新增损失。可信中心拟合、有标签原型损失、FedAvg 和 BN 策略不变。

“B 不变”是同一模型/输入下的目标计算不变；A 改变模型以后，B 预测、后续原型、上传统计和最终更新都会随训练轨迹改变，并非宣称它们的数值与旧实验逐轮相等。

风险证据分四组：

1. neutral：本类参考有效，没有足够的距离异常或竞争类别证据，A 权重为 1。
2. distance：超出本类半径，但尚未建立可信类别冲突。先验惩罚随距离异常平滑增加，上限 0.15。
3. conflict：竞争类别相似度比本类高超过 0.5×本类 margin_scale，图片同时处于竞争类别自己的半径范围内，且竞争参考 trust>0。上限 0.60，参考可信度取本类和竞争类中较小者。
4. unknown：本类参考无效或有效类别少于两类，不因参考缺失扣权。

0.15/0.60、间隔倍数和先验量 8 是本实验的固定设计值，不是已经验证的最优值。0.15/0.60 是乘参考可信度、启动门控和年龄衰减之前的惩罚上限。因此权重全局下界分别为 0.85/0.40，实际通常更接近 1。

## 校准如何工作

在原有每个本地 epoch 的参考提取中复用同一次 eval forward 的 logits，无新增随机增强或额外模型前向。查询集合与原参考拟合的交替 support/query 划分一致。仅使用真标签查询、高于当前 A 门槛的预测，按预测类别、置信度是否达到 0.99、证据组统计 count/errors。

先用同一置信带和证据组的其他类别形成池化统计，再向当前预测类别收缩；池化排除当前类别，避免重复计数。每个 epoch 重新建立统计，不把同一图片反复访问当成新的独立样本。

设几何先验惩罚为 p0，其他类统计为 (E_pool,N_pool)，本类为 (E_c,N_c)，先验量 k=8：

```text
p_pool = (E_pool + k*p0) / (N_pool + k)
p_class = (E_c + k*p_pool) / (N_c + k)
p = min(p_class, 本证据组的惩罚上限)
A_weight = 1 - gate * exp(-age) * reference_trust * p
```

没有校准样本时自然退回几何先验。查询曾参加监督训练，估计可能偏乐观；这是带先验的启发式风险惩罚，不是经过独立验证的正确率概率。校准使用 eval logits，训练伪标签来自现有训练分支；两者类别不一致或 eval 置信度未达门槛时，仅采用几何先验，不套用不匹配的校准。

不根据“猫整体较差”直接给猫统一扣权，不改变 B/C 分组，不用全批权重归一化补偿被扣掉的训练量，也不在服务器重复进行客户端质量扣权。

## 新日志

- `risk_audit.csv`：从实际启用轮开始，按轮次、客户端、预测类别、证据组，记录 A 访问量/正确量、同一批样本上的旧/新权重总量、错误权重总量，以及具有匹配校准样本的访问量。正确权重=总权重−错误权重。这是同一新模型上两种规则的对照，不是旧实验反事实训练结果。统计是真实样本访问次数，非独立图片数或梯度大小。
- `risk_calibration.csv`：逐 epoch、类别、置信带、证据组的有标签查询计数与错误数。置信带 0 为 [当前 A 门槛,0.99)，1 为 [0.99,1]。跨 epoch 累加不能当作独立样本量。
- 原 `metrics.csv`、`dynamics.csv`、`geometry_audit.csv` 反映新 A 实际权重。旧几何审计仍沿用旧支持/反对定义，新四组应查看 risk_audit，不能混用定义。
- `update_snapshots/round_0082.pt`、`round_0083.pt`、`round_0084.pt`：保存更新前全局、各客户端训练后和融合后的 CPU 状态（含 BN）、客户端 IDs、聚合数据量和参数名。它们是离线诊断快照，不是恢复训练检查点；不在线评估或拒绝更新，不使用测试标签影响训练。

无标签真实标签只在权重计算完毕后进入诊断计数。测试准确率不参与风险拟合、权重或快照选择。

## 如何判断有效

同时比较完整 300 轮最高值、最终值、最后 30 轮平均，以及中期回落。检查 distance/neutral 中正确 A 权重是否恢复，conflict 中错误权重是否受到控制，并检查各预测类别。单纯 loss 更小、整体权重更高、曲线更平都不构成成功证据。

最主要的研究风险是：恢复学习力度的同时放过更多错误答案，或者查询过于容易导致扣权不足。此实验不承诺解决第 83 轮或达到 88%；快照用于随后诊断独立的更新/BN 问题。

## 本机验证

CPU 测试覆盖缺失参考、竞争类不可信、校准仅使用查询、稀疏统计收缩、eval/train 不一致回退、诊断标签隔离、原前 30 轮一致，以及三个训练阶段真实优化器冒烟。完整 CIFAR10 GPU 训练由服务器执行。

上传时需要同步 `trusted_risk.py`、`trusted_geometry.py`、`fl_runner.py`、`options.py`、`update_diagnostics.py`、`scripts/run_experiment.sh`、`configs/experiment_trusted_lr015_risk.yaml`；测试和此文档建议一起保留。
